permissionsAn ordered list. For each action the last rule that matches wins. A pattern ending in * matches the command with or without arguments. A command joined with && or ; is split, and every part is checked.قائمة مرتّبة. لكل إجراء تفوز آخر قاعدة مطابقة. والنمط المنتهي بـ * يطابق الأمر مع وسائط أو بدونها. والأمر الموصول بـ&& أو ; يُقسَّم ويُفحص كل جزء منه.

Why this file matters on v2لماذا يهمّ هذا الملف في v2
  • Without any config, v2 allows everything. Its built-in policy is "allow all actions", and it only asks before reading .env files.
  • Folders outside the project are open by default. With no rule, the agent can read ~/secure/syravia/ without a prompt. The last five rules in the file close that.
  • So check after the merge that OpenCode really picked the file up (checks 3 and 4 in section 7).
  • بدون أي إعداد، v2 يسمح بكل شيء. سياسته المدمجة «السماح بكل الإجراءات»، ويسأل فقط قبل قراءة ملفات .env.
  • المجلدات خارج المشروع مفتوحة افتراضياً. بلا قاعدة يستطيع الوكيل قراءة ~/secure/syravia/ دون سؤال. والقواعد الخمس الأخيرة في الملف تغلق ذلك.
  • فتحقق بعد الدمج أن OpenCode التقط الملف فعلاً (الفحصان 3 و4 في القسم 7).
  • When it asks, you can answer once, always or reject. "Always" is saved for this project and stays after you close OpenCode, so use it only for commands you would allow every time. A saved approval never overrides a "deny" in the file.
  • "Reject" also rejects every other request waiting in that session.
  • The shell warning from the OpenCode docs applies: a command runs with your own rights on the machine, and OpenCode's reading of which folders a command touches is best effort. That is why the file allows a short list and asks for the rest, instead of trying to list every dangerous command.
  • The agents add their own rules after these. The plan agent cannot edit project files at all; the build agent follows the file.
  • عند السؤال تجيب مرة واحدة أو دائماً أو رفض. «دائماً» تُحفظ لهذا المشروع وتبقى بعد إغلاق OpenCode، فاستخدمها فقط للأوامر التي تسمح بها كل مرة. والموافقة المحفوظة لا تتجاوز «deny» في الملف أبداً.
  • «رفض» يرفض أيضاً كل طلب آخر منتظر في تلك الجلسة.
  • تحذير الطرفية في توثيق OpenCode ينطبق: الأمر يعمل بصلاحياتك أنت على الجهاز، وتقدير OpenCode للمجلدات التي يمسّها الأمر تقريبي. ولهذا يسمح الملف بقائمة قصيرة ويسأل عن الباقي، بدل محاولة سرد كل أمر خطر.
  • الوكلاء يضيفون قواعدهم بعد هذه. وكيل plan لا يستطيع تعديل ملفات المشروع أصلاً؛ ووكيل build يتبع الملف.

5 · Svelte: the rules and the Svelte tool5 · Svelte: القواعد وأداة Svelte

Your rules say: after every change to a .svelte file, run the Svelte autofixer until it reports nothing, and look up SvelteKit and Svelte APIs in the documentation tool instead of guessing. The rules come from CLAUDE.md (section 3). The tool comes from the svelte entry in the config.

تقول قواعدك: بعد كل تغيير في ملف .svelte شغّل المصحّح التلقائي لـSvelte حتى لا يُبلغ عن شيء، وابحث عن واجهات SvelteKit وSvelte في أداة التوثيق بدل التخمين. القواعد تأتي من CLAUDE.md (القسم 3). والأداة تأتي من مدخل svelte في الإعداد.

opencode mcp list
  • It should show svelte as connected. The first start downloads the server with npx, so it needs the internet once.
  • Test it with the prompt in section 7.
  • Other way: Svelte publishes an OpenCode plugin, @sveltejs/opencode, which adds the same tool plus a Svelte file-editing helper. In v2 it would go in the config as "plugins": ["@sveltejs/opencode"]. By default it uses Svelte's online server, so the .svelte code it checks is sent there. I chose the local server to keep with your "no cloud" rule.
  • If the local server does not start, replace the entry with the online one: { "type": "remote", "url": "https://mcp.svelte.dev/mcp" }. It only ever receives code, never data.
  • يجب أن يظهر svelte متصلاً. أول تشغيل ينزّل الخادم بـnpx، فيحتاج الإنترنت مرة واحدة.
  • اختبره بالنص في القسم 7.
  • طريقة أخرى: تنشر Svelte إضافة لـOpenCode هي @sveltejs/opencode تضيف الأداة نفسها مع مساعد لتحرير ملفات Svelte. في v2 تُكتب في الإعداد "plugins": ["@sveltejs/opencode"]. وهي افتراضياً تستخدم خادم Svelte على الإنترنت، فيُرسَل إليه كود .svelte الذي تفحصه. اخترتُ الخادم المحلي التزاماً بقاعدتك «لا سحابة».
  • إن لم يعمل الخادم المحلي فاستبدل المدخل بالخادم على الإنترنت: { "type": "remote", "url": "https://mcp.svelte.dev/mcp" }. وهو يستقبل كوداً فقط، لا بيانات أبداً.

graphifygraphify

  • The command-line tool works as it is. The agent runs graphify query "…", graphify path, graphify explain and graphify update . like any other command. CLAUDE.md section 7 already tells it when.

  • القواعد كما هي: مخطط هذا المستودع فقط، لا ~/secure/syravia/ ولا إضافة أودو القديمة، ولا الخلفية السحابية (Gemini) أبداً.

RTKRTK

In Claude Code, RTK works through a hook that rewrites each command (git status becomes rtk git status). That hook does not exist in OpenCode. RTK ships its own OpenCode plugin instead:

في Claude Code يعمل RTK عبر خطّاف يعيد كتابة كل أمر (git status يصبح rtk git status). هذا الخطّاف غير موجود في OpenCode. ولدى RTK إضافة خاصة بـOpenCode:

rtk init -g --opencode
  • It writes ~/.config/opencode/plugins/rtk.ts. Restart OpenCode afterwards.
  • This is the part most likely not to work on v2. The plugin was written for OpenCode 1, where the command tool is called bash; in v2 it is called shell. Test it: note the number in rtk gain, let the agent run a few commands, and look again. If the number did not move, the plugin is not active.
  • Fallback that always works: RTK is also a normal command. Add this line to your prompts, or ask me to add it to CLAUDE.md: "Prefix shell commands with rtk (for example rtk git status, rtk pnpm test); use rtk proxy when the full output matters."
  • Without RTK nothing breaks. The agent only spends more tokens on command output.
  • تكتب ~/.config/opencode/plugins/rtk.ts. أعد تشغيل OpenCode بعدها.
  • هذا أكثر جزء يُحتمل ألا يعمل على v2. الإضافة كُتبت لـOpenCode 1 حيث تُسمّى أداة الأوامر bash؛ وفي v2 اسمها shell. اختبرها: سجّل الرقم في rtk gain، ودع الوكيل يشغّل بضعة أوامر، ثم انظر ثانية. إن لم يتحرك الرقم فالإضافة غير فعّالة.
  • بديل يعمل دائماً: RTK أمر عادي أيضاً. أضف هذا السطر إلى نصوصك، أو اطلب مني إضافته إلى CLAUDE.md: «ابدأ أوامر الطرفية بـrtk (مثل rtk git status وrtk pnpm test)؛ واستخدم rtk proxy عندما يهمّ الناتج الكامل.»
  • بدون RTK لا يتعطل شيء. الوكيل فقط ينفق رموزاً أكثر على نواتج الأوامر.
